## 中英文支持

2026-10-10 用户追加开源及中英文支持。默认跟随系统：中文语言环境使用简体中文，其它语言回退 English；设置可显式选择「简体中文」或「English」，即时更新并保存，不修改系统或 Codex 语言。设置窗为 440 × 530 pt，原生选择器及紧凑修饰键复选框容纳英文标签；胶囊的冻结尺寸与动效保持原参数。

语言唯一来源为 `Resources/Localization/en.json` 与 `zh-Hans.json`，经 `generate_localizations.py` 校验键及格式占位符、生成不可变 Swift 表；`LanguageStore` 统一驱动菜单、设置、胶囊、错误、通知和辅助功能文案。日期跟随当前产品语言、用户地区及本地时区，数字不改变业务含义。服务提供的额度桶名称原样保留；实际窗口时长使用本地化描述，未知不补成 0。英文紧凑倒计时使用 `Resets in 5h` 等短文案，完整辅助说明保留自然语言。

安装画布提供中英双语引导，目标文件夹统一标为 `Applications`；原生文件及菜单操作仍由 Finder 管理。README 产品图只使用明确标注的合成示意，不公开真实账户截图。

## 应用图标与手动安装界面

用户追加美化正式应用图标与 DMG。延续细线胶囊：深色圆角底、胶囊轮廓、青绿色额度段及单个光点，不使用百分比、账户状态或仿官方 Codex 标识。图标提供 16–1024 像素的完整 ICNS，较小尺寸作描边补偿；图稿随应用签名封装。

DMG 使用浅色固定画布、原生应用和 `Applications` 图标，中间细箭头表达安装方向，中英双语提示说明拖入和安装后弹出。Finder 负责选择、拖放、键盘复制与粘贴，不绘制伪按钮；除应用及目标文件夹外不放可见杂项。背景为 2× TIFF，窗口为 640 × 460 pt，图标 96 pt；下方保留余量以容纳 Finder 用户偏好启用的路径 / 状态栏。背景提示是补充，文件名称及系统键盘操作仍可独立使用。

色板沿用 `design/v0.1/tokens.json`；安装布局唯一来源为 `design/distribution/layout.json`，由 `scripts/render_artwork.swift` 和 `scripts/dmg_settings.py` 共用。`scripts/artwork.py` 生成 ICNS / PNG / TIFF；`build_app.py` 嵌入图标并设置 Info.plist，`package_release.py` 生成 Finder 布局后重新签名公证。此追加不改变胶囊自身的冻结布局和动效。

## 已确认样式（2026-10-08）

- 采用「细线胶囊」作为第一版样式基准。
- 侧边吸附采用水滴融入屏幕边缘的连接轮廓：贴边处上下为反向圆角，外侧保持凸圆角。
- 用户进一步要求减小连接弧度与外侧圆角：冻结连接弧度 **8 px**、外侧圆角 **10 px**；原生实现采用对应 pt 并核对视觉一致性。
- 水滴、主体、细轮廓和阴影共用连续形状，避免分块拼接的锯齿及矩形阴影与反向圆角不贴合。
- 左右吸附镜像处理；悬停伸出保留侧边连接，拖离侧边后恢复完整胶囊。
- 吸附伸缩必须固定贴边锚点：左侧固定左边缘，右侧固定右边缘，仅向屏幕内部改变宽度，不同时动画移动横坐标。紧凑和悬停状态统一为 36 pt 高，连接弧度位置不随伸缩漂移。
- 本次冻结 UI、交互和动效；原生实现及本地交付完成，技术 / 实机证据与用户明确延期项目见 `V0.1-PLAN.md`。微型胶囊不纳入 v0.1。

## Codex 窗口内侧吸附（2026-10-13 追加）

屏幕吸附与 Codex 窗口吸附并存，沿用同一套 54 × 36 pt 标签、204 pt 悬停宽度、280 pt 详情卡片、连续轮廓和 32 pt 吸附行程。窗口吸附固定在 **Codex 主窗口的左或右内边缘**，向窗口内部伸展；拖动、缩放后保持相对纵向位置。展开与收起以同一个紧凑标签顶部为锚点，不因读数或卡片高度改变而累积位移。

- 拖近只有一个目标的边缘并松开，直接吸附；「位置」菜单也提供屏幕左 / 右及 Codex 窗口左 / 右的独立入口。
- 最大化、贴边或两个边缘距离很近时，如果两个目标同时满足 32 pt 行程，拖动中保留自由胶囊；**松开后弹出原生「选择吸附对象」菜单**，列出实际侧别的屏幕与 Codex 窗口选项。不得默认替用户选择任一对象。鼠标与键盘均可选择，Esc / 点击外部取消，取消后保持自由悬浮。
- 只读 Window Server 的所属进程、窗口 ID、边界、层级与可见状态；不读取窗口标题、画面或聊天，不请求辅助功能 / 屏幕录制权限。运行时锁定窗口 ID；跨启动只保存左右侧和相对高度，不持久化窗口 ID。
- 最小化、隐藏或切换到没有目标窗口的空间后暂时隐藏；回到可见 Codex 窗口后恢复。Codex 失焦不隐藏胶囊：胶囊使用略高于普通窗口的稳定层级，避免系统把跨应用面板推回宿主后方而造成闪烁。根据宿主前方窗口的只读几何裁切胶囊自身图层，保留未遮挡部分；被遮挡区域透过鼠标事件，不拦截 Finder 等窗口的操作。目标关闭后选择另一个可见 Codex 主窗口；没有窗口时等待重开。菜单中的窗口吸附入口在无可见窗口时禁用。
- 窗口跨屏时按所选内边缘所在显示器定位；边缘实际离屏时隐藏，不能把胶囊错贴在显示器边缘。手动隐藏具有最高优先级；切回屏幕 / 自由位置会结束窗口跟随。屏幕位置与窗口位置分别保存。
- 位置查询与视觉动画独立调度：窗口静止时以 30 Hz 检查已选窗口，发现移动 / 缩放后恢复 CADisplayLink 随当前显示器刷新（60 / 120 Hz），连续 350 ms 无变化后再降频。静止时开始移动的理论检测等待不超过一个 33.3 ms 查询周期（实际还受主线程调度影响）。同一份当前屏幕窗口元数据快照用于匹配宿主和计算遮挡，缓存所属进程集合；不读取标题和画面。高速拖动在真实宿主位移与最近鼠标轨迹匹配后，使用拖动事件即时定位并以几何采样校准；内容选中、缩放、窗口切换和过期轨迹不会触发预测。裁切位于 SwiftUI hosting view 外侧的稳定容器，防止 SwiftUI 重建背板时丢失遮挡。位置改变仅调用原生 setFrameOrigin，不发布 SwiftUI 尺寸变化；宿主移动不取消正在进行的展开动画。降频只暂停位置查询专用 display link，不限帧、不暂停展开 / 收起及额度流光的独立动画。不可见时改用 250 ms 重试；手动隐藏或退出后取消两种时钟。可见时不再反复调用跨应用排序；遮挡窗口的几何变化同样会唤醒高频位置查询，静止后恢复低频。应用激活 / 显示变化时立即刷新遮挡；覆盖区域的鼠标穿透由鼠标移动事件更新，不使用全局键盘监听。伸缩继续遵守系统减少动态效果。

实现归属：`DockingProposal` 负责候选与重叠判断，`WindowDockPosition` 负责坐标和持久化几何，`SystemCodexWindowSource` 负责白名单元数据，`OverlayController` 负责菜单、跟随和生命周期。窗口移动、缩放、最小化恢复、目标选择必须有真实桌面证据，合成测试不替代实机验收。

## 信息密度

常驻胶囊起始尺寸约 180 × 36 pt，而非固定物理像素。显示「97% · 6 天后重置」和一条细额度线；百分比明确表示剩余。不给品牌文字、设置按钮和次要数字永久占位。

有多个额度窗口时，默认选择剩余比例最低的窗口；并列时优先更早重置者，再用稳定标识决定。小面板展示全部有效窗口及名称。未知数据不参与排序，也不伪造耗尽状态。

胶囊固定使用「97% · 6天后重置」一类自然表达（本文数字均为合成示例）；前者是剩余百分比，后者是距重置的时间。不再并列「7天 · 7天窗」。窗口长度放在悬停辅助说明和详情中，详情原使用「codex · 7 天额度」（2026-10-13 改版后，默认桶省略重复的 codex 前缀，自定义桶仍保留名称）。准确窗口名称、完整百分比语义始终可通过辅助功能读取。（2026-10-08 用户语言优化反馈）

## 操作

- 拖动胶囊空白区域移动，设置移动阈值以区分点击和拖动。
- 按未吸附时的预期位置计算与左右边缘的间距，32 pt 内进入融合行程；移动 5 pt 后才判定为拖动。
- 拖动按住期间进入吸附范围，就固定贴边端并显示反向连接弧度，保持展开宽度；松手才收成标签。继续向内拖离范围时立即恢复自由胶囊，不必先松手。
- 吸附标签始终留在可用屏幕区域内，不藏到不可访问的位置。
- 鼠标靠近吸附标签时展开为胶囊；离开后延迟约 400 ms 收回。点击也能展开，不依赖悬停。
- 点击胶囊展开详情，再次点击、点击外部或 Escape 收起。
- 面板默认不抢其他应用键盘焦点；键盘主动打开时提供可访问的焦点路径。
- 菜单栏提供显示/隐藏、刷新、开机启动开关及退出。隐藏快捷键需检测冲突并允许修改。
- 同一用户只允许一个驻留实例；再次启动显示现有胶囊，正式与演示模式也不并行。（2026-10-08 用户追加）
- 吸附后展开的长条右侧显示图钉，点击切换固定；固定时鼠标离开、关闭详情和重启均保持长条。再次点击取消固定，恢复 400 ms 离开收缩。图钉不触发详情点击或拖动；自由胶囊不显示图钉。为容纳独立点击区，吸附长条宽度为 204 pt，自由胶囊仍为 180 pt。（2026-10-09 用户追加）
- 保存屏幕标识、归一化位置、吸附侧。拔掉显示器后回退到主屏可用区域；不恢复到屏幕外。
- 普通桌面常驻可见；全屏应用和多个 Space 的可见策略在原型阶段实机验证，默认不遮挡演示和全屏内容。

## 动效

- 拖动期间直接跟随指针；吸附范围内贴边锚点固定，鼠标位移控制形变，避免跟手延迟。
- 贴边形变由鼠标位移驱动，预览默认融合/脱离行程 32 px。进入范围时按距离把凸圆角变成反向连接弧度，反向拖动沿同一路径还原；停住鼠标则停住形变。连接存续期间贴边端固定，超出行程解除连接时必须已经完整恢复圆角，禁止离开边缘后再延时恢复。该行程替代早期 360 ms 形变计时器，与悬停伸缩时长独立。
- 悬停伸缩及详情展开时长固定 **200 ms**（采用用户在预览中调整的值），曲线为 cubic-bezier(0.2, 0.85, 0.25, 1)。这不参与拖动形变。
- 数值更新短过渡，不持续翻滚；没有新数据时不启动动画计时器。
- 新鲜数据确认额度恢复后只播放一次 **520 ms 清晰轮廓闪光**：前 18% 保持高亮，线宽从 1.8 pt 回落至 0.65 pt 并淡出；禁止柔边外扩光晕。吸附时只画外露轮廓及连接弧，排除贴墙直边；自由状态沿完整轮廓闪光。仅靠本地倒计时归零不能判定重置成功。
- 低额度用进度线和文本提示，不持续闪烁。
- 系统启用减少动态效果时，取消自动位移过渡和闪光，使用直接状态切换。
- 检测到同一账户、同一额度周期内的实际消耗增加后，额度线上播放 3.2 秒的三次向内流光和细小光点，文字短暂提示「检测到额度消耗」。光效完全裁切在原有 2 pt 额度线内，仅改变亮度，不加粗、不向外扩散、不覆盖文字；没有新消耗证据时停止。减少动态效果时只显示文字。断线、过期、隐藏、休眠后停止；首次加载、换账户、换周期和缺字段不触发。（2026-10-09 用户追加及细线反馈）

工作状态另由官方生命周期 hooks 的元数据投影驱动：任一已确认会话工作时，2 pt 轨道的已填充额度段内持续循环同样的细线流光，文字为「Codex 工作中」。流光移动与裁切范围均与填充段一致，不能横跨未填充底轨；数值过渡时共用宽度，剩余 0 或未知时只保留工作文字，不扩展光效范围。等待许可、结束和中断后停止；其它会话仍工作时保留流光。减少动态效果只显示静态文字。真实额度下降的短暂提示是补充，不能替代用户要求的持续工作特效。（2026-10-09 用户再次验收及范围反馈）

每一圈都在接近左端时渐隐，完全透明后再从右端淡入，不能只在整个三圈周期的首尾淡入淡出。保留 3.2 秒 / 三圈的移动节奏；单圈前 12% 淡入、80% 开始渐隐、98% 完全透明，最后 2% 用于不可见的循环交接。这些比例由 `tokens.json` 生成原生参数，沿用现有细线范围。（2026-10-09 用户循环跳帧反馈）

光点、头部和尾迹共用额度线的水平中线，只作横向移动和透明度变化；取消光点的上下扰动，避免细线远看形成下斜的视觉效果。（2026-10-09 用户水平对齐反馈）

独立 App Server 的 `thread/loaded/list` 本机为空，不能观察桌面其它会话。本项目不扫描聊天日志，不调用会返回会话摘要的 `thread/list`，不跟随完整会话状态。helper 仅保留生命周期白名单和哈希标识，接入说明见 `ACTIVITY.md`。本机 hooks 已经用户授权安装并全部受信任，真实工作、Stop 及用户授权的实际审批等待 / 恢复已观察。未接入或证据失效时不以假循环冒充工作。

## 数据状态

- 首次加载：显示加载状态，不显示假百分比。
- 展开后的加载提示为「正在读取额度…」；无窗口时错误原因只显示一次，视觉提示和辅助功能说明使用相同文案。
- 读取成功：显示实际值，展开后可查看最近成功更新时间。
- 刷新失败：保留上次成功数据并立即标记连接异常；没有缓存则显示不可用。
- 超过 3 分钟未成功刷新：标记过期。锁屏期间允许停止刷新，但唤醒后不能把缓存当新数据。
- 54 × 36 pt 侧边标签在过期、连接异常、未登录、不可用或服务受限时，在细线右侧显示静态橙色感叹号，数字降低对比；不占数字宽度、不改变轮廓。沿用完整状态辅助说明及悬停提示，展开后显示原因。正常后台刷新及首次加载不显示此告警。（2026-10-20 用户反馈）
- 紧凑告警参数来自 `tokens.json` 的 `compactStatus`：符号 9 pt，距右侧 7 pt、底部 3 pt，与进度线间隔 6 pt。左右吸附、点数与百分比共用 `OverlayView`；减少动态效果时同样静态显示。
- 登录失效：提示打开 Codex 恢复登录，不在工具条内接管认证。
- 未返回可用重置次数时不显示为 0；返回 0 时可明确显示 0 次。
- 充值余额按下方 2026-10-16 追加规则展示，与套餐百分比、token 和可用重置次数区分。

原生外观采用系统字体、深浅色适配、轻量材质与细边缘。普通空闲状态保持静止；持续工作流光仅随已确认的生命周期状态播放。

## 内容裁切与显示顺序

### 无打断刷新（2026-10-18）

- 首次读取且没有快照时显示加载态；之后的自动 / 手动刷新保留完整上一份成功数据、卡片结构和成功时间，只在原刷新按钮位置显示进度。失败保留数值并标记异常，超过 3 分钟保持过期语义。
- `account/updated` 也用于初始化及同账户认证刷新，不能直接清空显示。通知触发身份复核；现有读取期间合并处理，前后账户核对仍有效。确认换号、明确退出登录或不支持的认证模式后才清除旧账户数据；缺少 email 的账户由响应中的后台身份绑定。
- 显示中的胶囊（含收起标签）复用同一个只读 App Server，保持原有 60 秒轮询。主动隐藏 / 宿主不可见后 10 秒空闲回收，读取失败或纯连接检查完成后也按空闲策略回收；休眠及退出立即释放。此策略增加显示期间约一个后台服务的驻留内存，以减少重复认证和初始化等待。
- 可见时失败最多等待 60 秒后重试，隐藏时仍按最多 15 分钟退避；从隐藏或宿主不可见返回时，数据超过 60 秒或已有读取错误即主动补刷。唤醒、解锁及用户会话恢复后立即复核；现有分钟时钟也检查已到期轮询，避免单次调度丢失后停更。所有路径遵守暂停与单请求约束，成功返回前继续保留过期语义。（2026-10-20）
- `QuotaNumberText` 只对服务确认的新数值执行 360 ms 数字字形过渡，细线沿用相同时长。相同文本不重复动画；首次加载、换号、切换额度窗口 / 点数模式重新建立数字身份，不跨语义滚动。减少动态效果时直接更新。
- 额度快照本身立即更新，不逐帧修改余额或成功时间；数字动画仅属于展示。刷新期间的工作状态与动画继续由原有生命周期信号控制，异常及过期仍停止工作动效。

### 充值点数切换（2026-10-16 用户追加）

- 任一有效窗口归零且该额度桶的 `credits.hasCredits` 为 true、`balance` 为合法正十进制数时，胶囊改为显示充值点数。多个耗尽窗口按重置时间、稳定标识选择具有余额者；不跨桶借用余额。订阅恢复或点数耗尽后重新按原规则显示百分比。
- `QuotaSnapshot.displayMode` 是显示模式的统一来源，`QuotaCredits` 保存每桶余额及标志；数值以 Decimal 处理。缺失、非数、负数、无法精确容纳的数值保持未知。无限额度而无数值余额不能显示假点数。沿用多桶优先及空多桶权威规则。
- 中英文统一使用 `k`（千）、`M`（百万）、`B`（十亿）等缩写，更高数量级使用 `T/P/E` 或科学计数法；数值后不拼接「点」或 `credits`，不用「万 / 亿」。缩写最多一位小数；未缩写最多两位；均向下截取并去掉末尾零。如 60,000 → 60k、60,123 → 60.1k、1,250,000 → 1.2M；正余额不足 0.01 显示 `<0.01`。
- 54 pt 标签保留两侧各 8 pt，数字可用宽度 38 pt。`CreditLabelLayout` 使用实际绘制的系统圆角等宽数字字体测量：先减少小数位，再从 14 pt 降至最低 12 pt，仍不足则采用科学计数法。所有宽度均只显示数值及数量级缩写；数字单行、不省略、不撑大轮廓，布局随伸缩宽度重新选择。
- 悬停、辅助功能和展开详情提供完整余额，以「充值剩余」/「Credits remaining」标识数值含义，不在数值后追加单位。详情增加「充值剩余」行并保留所有订阅窗口。点数模式的整条细线表示有可用余额，不表示剩余百分比，说明文字置于详情；工作流光仍由现有工作状态控制。
- 点数模式不套用订阅百分比的橙 / 红阈值；异常、过期及服务限制仍保留原提示和低对比线条。减少动态效果时停止流光。显示模式切换不触发消耗短反馈或恢复闪光；同模式内原有订阅消耗检测保持有效。

轮廓层与内容层分开：轮廓允许反向圆角延伸，文字必须裁切在主体内。宽度低于 100 pt 时仅显示主数值（剩余百分比或充值点数）；倒计时在 164–180 pt 区间渐显，收缩时按同样规则提前隐藏。百分比不压缩、不被倒计时挤出；点数按上述原生宽度测量规则排版。细额度条更新过渡为 360 ms。

闪电沿已填充段分布，水平宽度与填充段一致；短条按实际宽度压缩，不横跨未填充轨道。竖向光效包络为 10 pt，以原进度线中线为中心，不覆盖文字或改变点击区。填充条的深浅色及 Codex 强调色沿用现有色板，低额度仍使用原有橙 / 红色。闪电独立采用金色：深色核心 #FFD23F / 光晕 #FFB414，浅色核心 #BD7D05 / 光晕 #E6A321；根据 SwiftUI 实际背景明度选择明暗金色，自定义主题不依赖系统 Aqua / Dark Aqua 判断；外观切换实时重着色，不把速度强度当成告警。动效由预建 CALayer / CAShapeLayer 合成，不添加逐帧 SwiftUI 时钟。结束、许可等待、隐藏、睡眠、额度异常 / 过期和 0 / 未知填充时停止；减少动态效果保留静态状态。真实额度下降的短反馈仍为 3.2 秒，选档不触发消耗或额度恢复闪光。

电弧采用程序化分形中点位移：四层递归细分，扰动按 0.55 衰减，每次放电具有独立种子、非等距折点和较细的短分叉；端点固定在进度中线上。时间扰动是连续的正弦噪声混合，同一放电保持拓扑，不逐帧重新抽签。分别预生成四个兼容路径，由 Core Animation 插值；strokeEnd 先推进放电前沿、strokeStart 后追赶消散，分叉延迟点亮，亮度具有短促回闪。细亮芯与低不透明度的强调色光晕分层，替代固定三条白色折线整体闪烁。快速为单通道分叉电弧；超快增加独立种子的第二通道，以较细、稍弱的核心和 14% 寿命延迟交错传播，分叉强度也更高。小于 1 pt 的可用电弧长度只保留原流光。

技术依据为 [Jim Bumgardner 的中点位移生成示例](https://jbum.com/bestiary/bestiary_lightning.html)及 [NVIDIA Lightning SDK 的递归扰动、分叉与光晕方案](https://developer.download.nvidia.com/SDK/10.5/direct3d/Source/Lightning/doc/lightning_doc.pdf)。本实现针对 10 pt 包络使用二维程序化近似，并非物理介质击穿模拟；传播和连续扰动是本项目的小尺寸动效设计。

参数唯一来源仍为 `design/v0.1/tokens.json`，追加 `consumption.lightning`，由 `generate_tokens.py` 生成 Swift。紧凑胶囊和详情卡片共用 `QuotaProgressTrack`；`ConsumptionTraceLayerView` 保留原流光并负责三档图层，不复制绘制 / 裁切逻辑。

### 速度来源与诚实显示

只读同一 `CODEX_HOME/config.toml`，复用外观配置的父目录监听及 150 ms 合并更新；原子替换、删除和恢复都会重新投影。仅解释 `service_tier`、`profile` 及对应 profile 的速度字段：`default` / `standard` → 标准，`fast` / `priority` → 快速，`ultrafast` → 超快；缺失、不支持或歧义字段保持未知。显式 profile 速度优先，否则继承顶层值。这是保存的默认选择，不等于当前所有聊天的实际执行速度或计费证据。

可选聊天级覆盖只连接已经运行的官方本机 Unix WebSocket：校验 socket / 用户归属、WebSocket Upgrade 与帧，然后仅发送 initialize / initialized。控制路径可能是当前用户拥有的符号链接，必须核对解析后的私有 socket，不能把任意普通文件当服务。不启动 / 重启 daemon，不查询 model/list、线程历史或完整会话，不修改账户 / 配置。初始化退出已知非速度通知；其它载荷按字节跳过，只投影 `thread/settings/updated` 中 threadId 与 serviceTier。标识立即哈希，至多缓存 128 条设置于内存；仅匹配 hooks 已确认工作的会话，并选最高已确认档位。等待许可或停止的会话不参与汇总，断线 / 睡眠清空覆盖并回到配置默认值。WebSocket ping 仅按协议回复 pong，外部执行 / 批准请求直接关闭本连接。

未确认聊天档位、没有现有 daemon 或当前客户端未收到通知时，使用配置默认档位；配置也未知时沿用原流光。辅助功能区分“默认速度”与“工作速度”。不扫描历史猜测速度，不凭默认档位声称当前请求真正进入了某个计费服务层。当前 daemon 初始化通过不等于全部桌面、CLI、云端及私有 App Server 的通知覆盖都已验证。

### 左侧连接偏移修正

原紧凑状态的异常 / 演示图标用 opacity 隐藏，却仍参与 HStack 最小宽度计算，进而撑大 ZStack 中的轮廓；面板几何可以正确而可见连接处向外溢出。紧凑状态改为不创建该隐藏占位，轮廓与内容明确采用主体宽高。NSHostingView 不再按 intrinsic/minimum size 反向调整控制器拥有的窗口尺寸，遮挡容器确保 hosting 与实际 bounds 一致。左右连接锚点、相对纵向位置、200 ms 展开收起及现有偏好格式保持原约定；没有加入固定像素补偿。

### 流光中线追加修正

用户实机反馈白色光点偏上。工作状态的蓝色填充条与流光此前分别由 SwiftUI 和 NSView/CALayer 绘制，半点原点会独立取整。现将工作填充条、流光头、尾迹、电弧全部放在同一个原生图层坐标系，统一使用 bounds.midY，按实际 backingScaleFactor 绘制；静止 / 减少动态效果仍保留 2 pt 细条。不加纵向补偿常数。分数高度与宽度的几何回归、最终原生连续帧分别核验。

### 按实际填充长度减少电弧细节

用户指出拉长状态效果合适，紧凑状态的闪电挤在一起。光效按已填充段宽度适配，不能只按胶囊是否展开判断：

- 大于 64 pt：保留上述单 / 双通道、分叉、四层分形与辉光参数。
- 12–64 pt：只保留一束电流，关闭分叉和第二通道；长度最多占填充段 72%，幅度快速 1.5 pt / 超快 1.8 pt，折点数量按约 3 pt 的可读间隔减少；光晕描边倍率降为 1.6、辉光半径 0.65 pt，寿命为长条的 65%；单束描边放大 1.35 倍、峰值不透明度乘 1.2 并限制在 1，补偿减少细节后的可见度，不增加路径堆叠。
- 不超过 12 pt：改为沿原中线传播的短金色脉冲，无折点 / 分叉 / 第二通道，辉光半径 0.25 pt；可用长度不超过 1 pt 时只保留原流光。

短条通过描边、亮度与放电频率区分快速 / 超快，避免靠同时堆叠多条路径表达速度。所有档位继续裁切在实际填充宽度和 10 pt 高的包络内；长条效果与已修正的中线保持原样。规则由 PulseCore.LightningLayout 选择，参数来自 consumption.lightning；紧凑胶囊和低额度详情共用同一规则。
