# Codex Pulse v0.1 实施计划

制定日期：2026-10-07（Asia/Shanghai）

状态：2026-10-08 已冻结细线胶囊 UI、交互和动效，参见 `DESIGN.md` 和 `../design/v0.1/`。原生应用实现、编译及实机验收尚未开始。

## 目标与完成定义

交付一个能在用户 Mac 上日常使用的原生浮动胶囊：无需打开 Codex 设置即可查看剩余额度和重置时间；可拖动、左右吸附，界面紧凑，空闲时安静。

第一版交付包括本地可运行 `.app`、源代码、构建说明和验证记录。创建 GitHub 远程仓库、公开发布、签名公证及自动更新不属于本次初始范围。

## 范围

必须实现：

1. 当前登录账户的实际额度桶与窗口解析、剩余百分比、重置时间。
2. 横向胶囊、侧边标签和点击展开的小面板。
3. 拖动、吸附、位置记忆、多显示器拔插回退。
4. 60 秒额度轮询、手动刷新、唤醒补刷、请求去重及失败退避。
5. 加载、未登录、不可用、过期和正常数据状态。
6. 可用重置次数展示（字段存在时），只读。
7. 20% / 10% 低额度阈值提醒；通知权限由用户主动启用提醒时申请。
8. 菜单栏入口、显示/隐藏快捷键、可选开机启动。
9. 系统深浅色、减少动态效果、基本键盘和辅助功能支持。

明确不做：任务/子代理列表、确认请求处理、token 图表、模型信息、CPU/内存监控、聊天内容读取、多账户、积分换算、自动使用重置次数、跨平台版本。

## 实现方向

SwiftUI 管理内容和状态，AppKit NSPanel 管理不抢焦点的浮窗及显示器行为。先以 Swift Package 建立可测试核心与应用目标；打包脚本生成本地 `.app`。若平台能力需要 Xcode 工程，在验证后补充，不先引入无关依赖。

拟定模块：

- `QuotaClient`：本地 App Server 初始化、只读请求、超时、断线恢复与进程生命周期。
- `QuotaSnapshot`：动态额度桶/窗口、可选重置次数、成功时间和来源状态。
- `QuotaStore`：合并刷新、当前账户隔离、有限缓存与过期判断。
- `OverlayController`：胶囊/吸附/面板状态、显示器和窗口行为。
- `AlertPolicy`：阈值穿越提醒和每个额度周期去重。
- `Preferences`：位置、外观、提醒、快捷键和开机启动选择。

优先使用 `account/rateLimits/read`，支持多桶字段和旧单桶响应；按 `windowDurationMins` 决定窗口含义。剩余比例为 `100 - usedPercent`，对异常数值防御处理；缺失值保持未知。

账户额度来自服务，不从本机 token 推算。v0.1 无需 `account/usage/read` 或完整聊天记录。也不把本次聊天可用的内部工具当成独立应用可调用的接口。

能接收更新通知时可辅助刷新，但不能假设独立 App Server 能观察其他客户端全部实时变化；轮询负责兜底。探测具体连接与认证复用方式是第一个里程碑。

## 里程碑及顺序

| 阶段 | 工作与可检查产物 | 通过条件 | 估算 |
| --- | --- | --- | --- |
| M0 数据验证 | 核实本机工具链、Codex 可执行文件/协议；最小只读 quota probe；脱敏夹具 | 与同账户设置页在相近时间核对窗口/百分比/重置时间；探测无推理请求 | 0.5–1 天 |
| M1 原生外形 | 可运行胶囊，先用明确标注的演示数据；拖动、吸附、展开、关闭 | 用户实机确认尺寸和吸附手感；键盘焦点不被抢走 | 1–1.5 天 |
| M2 真实额度 | 接真实数据、动态窗口、刷新、缓存和错误状态 | 单周窗口、多窗口、空字段、断网均显示正确；演示数据不会混入正常模式 | 1 天 |
| M3 常驻体验 | 位置记忆、多屏、唤醒、快捷键、开机启动、阈值提醒和动效 | 常见桌面场景可用；提醒不重复；减少动态效果生效 | 1–1.5 天 |
| M4 验收打包 | 回归测试、空闲资源采样、本地打包、README 和验证记录 | 下方验收项通过；未通过项明确记录，不能称为可日用版本 | 1–2 天 |

整体预估约 5–7 个工作日，可运行的交互原型预计 2–3 天。估算基于单个 macOS 开发者使用 AI 辅助，不是已验证工时；接口连接和全屏/多屏兼容是主要不确定项。出现障碍先报告证据及范围影响。

## 刷新与提醒约定

- 可见时每 60 秒读取额度；展开时仅在上次成功读取超过 15 秒时补刷。
- 收起的侧边标签仍保持 60 秒额度更新；用户主动隐藏时可降为 5 分钟。
- 锁屏/睡眠时暂停，恢复后立即补刷；过期状态判断采用实际时间，不按计时器触发次数推断。
- 同时最多一个请求，超时后释放资源；失败使用有上限的退避，手动刷新仍遵守单请求约束。
- 重置倒计时在本地更新，显示分钟/天级时无需每秒重绘。
- 到达重置时间发起确认读取；请求失败不假设额度恢复为 100%。
- 提醒按账户、额度桶、窗口周期和阈值去重；首次读取已低于阈值时最多提醒一次，不能连续弹出两级通知。
- 成功读取后的真实额度周期变化才重建提醒状态；账户切换先清除旧账户显示，不能交叉沿用缓存。

## 验收清单

### 正确性

- [ ] 实机只读快照与同账户设置页在相近时间核对，注明采样时间与可能的刷新差异。
- [ ] 仅周窗口、5 小时+周窗口、多额度桶、空窗口均有合成夹具覆盖。
- [ ] 缺字段、无权限、登录失效、连接失败不会显示假 0% 或假 100%。
- [ ] 时间按用户本地时区显示；重置边界、系统时间变化不导致负倒计时或伪重置。
- [ ] 断网后的缓存明确显示异常/过期；恢复后更新成功时间。
- [ ] 重复通知、并发刷新和账户切换有针对性的逻辑测试。

### 桌面体验（必须真实操作，不能只看截图）

- [ ] 拖动跟手，点击不误判为拖动，左右吸附能展开和脱离。
- [ ] 不抢编辑器焦点；菜单栏、快捷键、Escape 和点击外部行为符合设计。
- [ ] 重启恢复位置，拔屏后回到可见范围，不同缩放显示器均可读。
- [ ] 睡眠唤醒后恢复刷新，多个 Space 和全屏行为符合约定。
- [ ] 深浅色、减少动态效果及长文本布局验证通过。
- [ ] 普通空闲状态不循环播放动效；低额度和重置反馈只发生一次。

### 资源与交付

- [ ] 在用户机器采集至少 10 分钟空闲数据：应用及其子进程 CPU、RSS、请求次数；分别记录应用和 App Server 开销。
- [ ] 初始性能目标：稳定空闲平均 CPU 小于一个逻辑核的 1%，总 RSS 争取低于 150 MiB；作为待验证目标，不能当作承诺。
- [ ] 退出后没有遗留的本应用子进程；不关闭用户原有 Codex 服务。
- [ ] 不扫描聊天历史；不向第三方服务发送账号或用量数据。
- [ ] 可复现构建命令、本地 `.app` 及验证记录齐全；未签名/未公证情况据实注明。
